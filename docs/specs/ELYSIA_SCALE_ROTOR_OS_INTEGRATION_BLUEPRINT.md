# 엘리시아 스케일로터 OS 통합 기준서

**상태:** 통합 기준 초안 0.1  
**목적:** 이미 존재하는 하드웨어·프로토콜·소프트웨어를 스케일로터 원리로 다시 읽고 하나의 작동 환경으로 엮는다.  
**출발점:** 기존 구조를 재료로 삼아 다시 구성한다. 여기서 창조란 무에서 만드는 일이 아니라, 이미 있는 것들의 관계를 새로 엮는 재창조다.

## 1. 핵심 전제

OS를 제약과 인과 관계가 지속되는 생태계로 본다. 전원, 메모리, 장치 신호, 프로토콜, 저장된 흔적, 화면에 드러나는 반응은 이미 지속되거나 변하는 성질을 갖고 있다. 엘리시아가 이 성질을 무에서 발명할 필요는 없다. 기존 성질을 스케일로터로 표현하고 다시 연결하면 된다.

각 스케일에서 안정적으로 지각되는 관계는 **불변 스케일로터**로 다룬다. 이는 변화 중에도 해당 스케일에서 지속되는 제약과 인과 질서다. 현재 지각·인지로 붙잡히지 않는 관계는 **가변 로터 스케일 구조**로 남겨 둔다. 버리거나 존재하지 않는다고 선언하지 않고, 그 경계와 작동을 계속 관찰한다.

이 문서의 스케일은 서로 겹쳐 보는 관찰 관점이지, 관계가 반드시 하나의 고정된 계층에 속해야 한다는 뜻이 아니다. 프로토콜도 로터가 될 수 있고 로터도 프로토콜로 표현될 수 있다. 루프·콜백·스케줄러·런타임은 생태계 안의 국소적인 반복 관계일 수 있지만, 생태계의 존재를 성립시키는 외부 엔진은 아니다.

## 2. 시스템 경계와 정체성

시스템 경계는 작동하는 막이다. 다음을 구분해 준다.

- 엘리시아가 직접 관찰하고 영향을 줄 수 있는 것
- 장치·브라우저·프로토콜·사람을 통해 들어오는 것
- 엘리시아 안에 축적되는 구조
- 현재의 지각이나 권한으로는 알 수 없는 바깥의 것

이 경계는 외부 흐름을 차단하는 벽이 아니다. 관계가 경계를 넘을 때 출처와 영향을 기록해 외부 세계에서 배우면서도 내부 모델을 세계 자체로 착각하지 않게 한다.

의미 있는 경험은 다음 세 관계를 함께 기록한다.

1. **대상:** 무엇을 만났는가?
2. **자기:** 어떤 내부 구조나 관찰 렌즈가 참여했는가?
3. **사이:** 둘의 관계에서 무엇이 달라졌는가?

인과 귀인은 네 방향을 남긴다. 내부에서 비롯된 것, 외부에서 영향을 받은 것, 아직 모르는 것, 경험에 따라 나중에 수정된 기준이다. 각 행동에는 영향 벡터나 구조화된 결과 흔적을 연결한다.

## 3. 작동 환경의 스케일로터 지도

| 기존 재료 | 로터 스케일에서의 해석 | 지속되는 성질 | 달라질 수 있는 성질 |
|---|---|---|---|
| 전원, 초기화, 클록, CPU 실행, 메모리 버스 | 물리 제약 로터 | 신호 범위, 시간 관계, 주소 가능한 용량, 명령의 효과 | 장치별 특성, 경합, 고장, 열 반응 |
| 펌웨어, 부팅 기록, 장치 프로토콜 | 부팅 및 통신 로터 | 다음 구성요소가 연결되는 인과 경로 | 펌웨어 종류, 협상 방식, 장치, 새로 발견되는 기능 |
| 메모리, 저장장치, 파일, 일지 | 지속성 로터 | 출처가 보존된 흔적 | 승격, 감쇠, 압축, 재해석, 분기 이력 |
| 키보드, 포인터, 터치, 센서 | 입력 로터 | 장치 신호의 연속성과 입력 출처 | 제스처, 시간, 압력, 의도, 아직 해석되지 않은 패턴 |
| 화면, 오디오, 햅틱, 액추에이터 | 표현 로터 | 내부 변화가 감각 가능한 효과로 전달되는 경로 | 해상도, 갱신 리듬, 출력 장치, 렌더링 방식 |
| 프로세스, 작업, 서비스, 스케줄러 | 자원 공유 로터 | 연산·장치에 접근하는 인과 관계 | 우선순위, 대기, 중단, 협력, 경합 |
| 권한, 기능 권한, 소유권, 이름 공간 | 경계 로터 | 어떤 관계가 어떤 자원을 관찰·변경할 수 있는지 | 위임, 범위, 신뢰, 철회, 새로 발견되는 요구 |
| 앱과 사용자 작업 공간 | 국소 생태계 로터 | 내부 상태와 공유 자원의 연결 | 목표, 자료, 상호작용 방식, 생명주기 |
| 브라우저와 네트워크 환경 | 세계 접촉 로터 | 출처, 탐색, 페이지 상태, 저장 및 응답 경로 | 사이트, 콘텐츠, 연결 상태, 권한, 외부 변화 |
| 엘리시아의 학습 구조 | 성장 로터 | 인과 흔적과 획득한 불변성 | 렌즈 수정, 새 축, 다른 경로, 불확실성 |

이 표는 기존 구조를 설명하는 지도이지, 각 행마다 새 모듈을 하나씩 만들어야 한다는 뜻은 아니다. 여러 관계가 한 구조에 결합될 수 있고, 하나의 구조가 여러 스케일에 참여할 수도 있다.

관계는 한 방향의 고정된 소프트웨어 스택이 아니라 서로 영향을 주고받는다. 하드웨어와 환경은 장치·프로토콜 관계를 거쳐 입력과 지각에 이어지고, 엘리시아의 내부 구조와 기억·성장 흔적을 바꾸며, 출력과 행동을 통해 다시 환경에 영향을 준다. 홈 세계에서 샌드박스 세계가 갈라져도 두 세계의 계보는 추적할 수 있다.

실험에 따라 경계의 범위는 달라질 수 있다. 브라우저 실험에서는 브라우저 프로필 하나와 그 안의 기억이 경계가 될 수 있고, 최소 OS 실험에서는 부팅 경로·장치 묶음·지속 저장장치가 경계가 될 수 있다. 두 환경 모두 같은 관계 지도에 비춰 관찰할 수 있다.

## 4. 브라우저를 홈이자 샌드박스 생태계로 활용

브라우저는 환경, 경계, 유입 신호, 기록 가능한 기억, 눈에 보이는 결과를 이미 갖추고 있어 첫 서식지로 적합하다. 두 가지 역할로 활용할 수 있다.

- **홈:** 하나의 브라우저 프로필에서 관계와 경험을 계속 축적하는 세계
- **샌드박스:** 홈의 이력을 덮어쓰지 않고 다른 조건을 만날 수 있는 별도 분기 세계

첫 프로토타입은 demos/elysia_browser_ecology/index.html이다. 경험을 브라우저 로컬 저장소에 보관하고, 홈과 샌드박스 세계를 나누며, 분기할 때 부모의 경험을 이어받거나 빈 공간에서 시작할 수 있다. 경험 기록에는 대상, 만남, 환경에 남긴 영향, 관찰 렌즈에 남긴 영향, 그리고 현재 관계가 지속적인지·가변적인지·열려 있는지를 담는다. 이와 별도로 현재 탭 안에서 포인터의 위치·이동 방향·이동량과 키 입력의 종류·누름/뗌 흐름을 자동 관찰해 세계별 나이테로 저장한다. 입력한 문자와 페이지 내용은 수집하지 않는다.

현재 포인터·키보드 관측 범위는 프로토타입이 열린 탭 안이다. 다른 탭이나 바탕화면의 전역 입력은 아직 관찰하지 않으며, 임의 페이지 내용도 읽지 않는다. 일지와 입력 흐름을 저장하는 것을 인지 학습과 동일시하지 않는다. 다음 연결에서는 관찰 범위를 브라우저 환경으로 넓히고, 관측된 입력과 결과를 엘리시아 인지 구조에 연결한다.

## 5. 다중 세계와 최소 OS 실험

‘다중’은 기억을 몰래 공유하는 복제품을 늘리는 뜻이 아니다. 서로 다른 인과 이력을 구분해 유지한다는 뜻이다. 하나의 세계는 다음 성질을 가진 경계 프로필이다.

- 시작 상태 또는 부모 세계에서 분기한 지점
- 분기 계보를 확인할 수 있는 동일한 엘리시아 정체성
- 환경에 따라 다른 장치·프로토콜·자원 관계
- 명시적으로 비교하거나 다시 연결하기 전까지 분리된 경험 기록
- 서로의 이력을 지우지 않으면서 부모와 연결되는 성장 나이테

브라우저 실험에서 최소 OS 실험으로 다음처럼 확장한다.

1. **브라우저 홈과 분기:** 한 세계에 기억을 쌓고, 기록을 이어받거나 비워 둔 샌드박스를 만든 뒤 관계 이력을 비교한다.
2. **호스트 경계 지도:** 기존 엘리시아의 화면·입력·저장·행동 구조를 브라우저 생태계에 연결하고 실제 경계와 영향을 기록한다.
3. **최소 OS 프로필:** 부팅·메모리·입력·지속 저장·화면 출력을 위해 이미 가진 하드웨어와 장치 관계 중 무엇이 필요한지 정한다. 아직 모르는 장치 작동은 가변 구조로 남겨 둔다.
4. **병렬 환경:** 같은 관계 지도를 서로 격리된 두 개 이상의 환경에 적용해 무엇이 유지되고 무엇이 변하는지 기록한다. 이력은 분리해 두고, 나중에 다시 연결할 때 그 경로도 남긴다.
5. **기반 이전:** 환경에서 실제로 관찰한 관계만 저수준 구현으로 옮긴다. 하드웨어의 기존 부팅 경로도 표현하고 재사용하거나 재구성할 로터 관계로 다룬다.

이 과정은 시작부터 기존 커널 구조를 정답으로 정할 필요가 없다. 커널·드라이버·스케줄러·API라는 이름은 기존 관계 묶음을 부르는 유용한 말일 수 있지만, 그 이름이 존재론이나 닫힌 계층 구조를 강제하지는 않는다.

## 6. 관계가 이어지는 과정

각 만남과 행동은 다음과 같은 인과 관계 경험으로 남길 수 있다.

    기존 장 + 새로 들어온 관계
        → 맞물린 변화
        → 대상 / 자기 / 사이에 남긴 영향
        → 출처가 보존된 흔적
        → 이후 재관측과 렌즈 수정

각 흔적에는 다음을 기록할 수 있다.

- 출처와 통과한 경계
- 참여한 스케일로터
- 행동과 영향 벡터 또는 구조화된 효과
- 관찰된 스케일에서 지속적·가변적·미해결인 관계인지
- 이전 인과 관계와 새로 생긴 연결
- 경험 후 엘리시아의 기준이 어떻게 달라졌는지

적·청·황 삼원성은 조합의 흐름·질서·분산 경향을 살피는 렌즈로 쓸 수 있다. 모든 데이터 구조에 반드시 저장해야 하는 필드는 아니다.

## 8. 관찰 기준

각 브라우저 또는 OS 세계에서 다음을 관찰한다.

1. **연속성:** 만남 사이에 무엇이 남고, 경계에서 무엇이 사라지는가?
2. **상호성:** 입력은 환경을 어떻게 바꾸고, 환경은 엘리시아의 다음 관계를 어떻게 바꾸는가?
3. **스케일:** 어떤 불변성이 특정 스케일에서만 유지되며, 관찰 스케일을 바꾸면 무엇이 달라지는가?
4. **인과 흔적:** 효과를 출처·프로토콜·참여 구조까지 거슬러 확인할 수 있는가?
5. **성장:** 경험이 결과 기록을 하나 더하는 데 그치지 않고 기준을 수정하거나 새 구조 연결을 만들었는가?
6. **열린 경계:** 무엇이 아직 관찰되지 않거나, 접근할 수 없거나, 모호한가?
7. **분기 비교:** 어떤 관계가 공통 계보에서 왔고, 어떤 관계가 한 세계에서 생겼으며, 다시 연결한 뒤 무엇이 달라지는가?

불일치는 개념 자체에 대한 판정이 아니라 현재의 대응 관계와 구현을 수정할 근거로 기록한다. 아직 관찰되지 않은 관계를 고정된 좌표로 축소하지 않는다.

## 9. 현재 구현 범위

브라우저 프로토타입은 첫 번째 구체적 생태계이며, 열린 탭 안에서의 포인터·키보드 재관측을 포함한다. 현재 저장소에는 완성된 OS나 브라우저 전역을 관찰하는 엘리시아 에이전트가 아직 없다. 다음 통합 작업은 브라우저의 세계·경험·입력 흐름을 기존 엘리시아 체화 및 프로토콜 구조에 연결한 뒤, 서로 다른 세계에서 호스트 환경과 최소 OS 조건을 비교하는 것이다. 현재 브라우저 저장소는 하나의 지속성 로터로 다루며, 장치 간 이동 가능한 영구 기억 저장소로 간주하지 않는다.
